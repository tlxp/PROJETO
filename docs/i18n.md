# Internacionalização (PT / EN)

O ecossistema suporta **Português** e **English** de forma coordenada entre a aplicação desktop WPF, a interface web e mensagens de fallback da API.

## Onde o idioma é definido

| Camada | Mecanismo | Persistência |
|--------|-----------|--------------|
| **WPF** | Ecrã `LanguageSelectionView` no primeiro arranque; botão *Idioma* no dashboard | `%LOCALAPPDATA%\RatAnalyzer\ui-settings.json` |
| **Frontend** | Parâmetro `?lang=pt\|en` na URL; `localStorage` (`ratanalyzer-lang`); env `VITE_DEFAULT_LOCALE` | URL + `localStorage` |
| **Backend** | Env `RATANALYZER_LANG`; header HTTP `Accept-Language` | Processo uvicorn (propagado pelo WPF no arranque) |

Ordem de resolução no **frontend web**: `?lang=` → `localStorage` → `VITE_DEFAULT_LOCALE` → `pt`.

## Propagação a partir do WPF

Quando o WPF arranca backend e frontend:

1. Define `RATANALYZER_LANG` e `VITE_DEFAULT_LOCALE` nos processos filhos (`AppConstants.PropagateLanguageEnvironment`).
2. Envia `Accept-Language` nos pedidos HTTP ao backend (`StaticAnalysisService`, `DynamicAnalysisService`).
3. Abre o browser com `?lang=` — ex.: `http://localhost:8080/analysis/{jobId}?lang=en` (`AppConstants.BuildFrontendUrl`).

## O que é traduzido

| Área | PT/EN |
|------|-------|
| UI WPF (dashboard, loading, diálogos, janelas VM/storage) | Sim |
| Logs de arranque visíveis no WPF (`LogCatalog`) | Sim |
| Mensagens de progresso da análise estática/dinâmica (WPF) | Sim |
| Interface web (upload, resultados, erros, labels de relatório VM reformatado) | Sim |
| Fallbacks da API (relatório/bytecode em falta, erros de job) | Sim |
| Relatórios gerados pelo pipeline (Ghidra, VM PowerShell) | Idioma original do gerador |
| Scripts PowerShell da sandbox | Português (ver [`ps1-scripts.md`](ps1-scripts.md)) |

## Desenvolvimento

### WPF

- Catálogo: `wpf-gui/Localization/` (`LocalizationManager`, `LocKeys`, `LogCatalog`, `UiStrings`).
- Novas strings de UI: adicionar chave em `LocKeys.cs` e entradas PT/EN em `LocalizationManager.cs` ou `LogCatalog.cs`.

### Frontend

- Mensagens: `frontend/src/i18n/messages.ts` (objetos `pt` e `en`).
- Em componentes React: `useI18n()` → `t("chave")`.
- Fora de React (`api.ts`, `analysis.ts`): `getT("chave")` de `@/i18n`.

### Backend

- Mensagens: `backend/i18n.py` (`MESSAGES`, função `t()`).
- Uso: `from i18n import current_lang, t` e `t("report_not_generated", current_lang())`.

## Variáveis de ambiente

| Variável | Valores | Componente |
|----------|---------|------------|
| `RATANALYZER_LANG` | `pt` \| `en` | Backend (fallbacks de API/relatório) |
| `VITE_DEFAULT_LOCALE` | `pt` \| `en` | Frontend dev server (propagado pelo WPF) |

## FAQ rápido

**Mudei o idioma no WPF mas o localhost continua em português** — Recarregue com `?lang=en` ou feche e reabra a página de resultados (o WPF acrescenta o parâmetro automaticamente). Se o dev server já estava a correr antes da mudança, o `VITE_DEFAULT_LOCALE` só aplica após reinício do frontend.

**Posso mudar o idioma só no browser?** — Sim, `http://localhost:8080/?lang=en` (ou `pt`). O valor fica em `localStorage`.
